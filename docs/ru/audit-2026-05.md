`parsers/*`, Docker, скрипты, документация. Целевое развёртывание: сервер в
локальной сети / команде и локальные рабочие станции, не публичный интернет.

## Находки

### 1. Зависимости с известными уязвимостями (высокий приоритет)

`govulncheck` показывает пути кода, которые реально выполняются.

Корневой модуль:

- `golang.org/x/net v0.53.0`, достигается через `html.Parse`:
  GO-2026-5030, 5029, 5028, 5027, 5025 (XSS через дублирующиеся атрибуты,
  DoS на произвольном HTML, обработка foreign content). Исправлено в
  v0.55.0; v0.56.0 закрывает и две «подключённые, но не вызываемые»
  (GO-2026-5942, 5026).
- `github.com/modelcontextprotocol/go-sdk v1.0.0`, достигается из
  `cmd/marvindocs/main.go` и `internal/mcpserver/server.go`:
  GO-2026-5771 (защита от DNS rebinding выключена по умолчанию на
  localhost), GO-2026-4773 (cross-site выполнение инструментов для HTTP
  серверов без авторизации), GO-2026-4770 (NUL в JSON), GO-2026-4569
  (регистр символов). Исправлено в v1.4.1; актуальная v1.8.0.

Парсеры:

- `parsers/go-dev`: те же 5 проблем `x/net` через `dev.extractArticle`
  (`parse.go:70`).
- `parsers/laravel`: GO-2026-5208, чтение за границами буфера в
  `gomarkdown/markdown` `SmartypantsRenderer`; исправлено в
  `v0.0.0-20260411013819-759bbc3e3207`.

Две проблемы `go-sdk` важнее всего для развёртывания в LAN: браузер в той
же сети может обратиться к `POST /mcp`, если не задан `--auth-token`.
Сейчас токен необязателен.

Прочие устаревшие прямые зависимости: `html-to-markdown/v2` 2.5.0 -> 2.5.2,
`go-sqlite3` 1.14.42 -> 1.14.52.

### 2. Файл индекса в ~10 раз больше необходимого (высокий приоритет, дешёвое исправление)

`marvindocs.db` занимает 4,49 ГБ; копия после VACUUM — 429 МБ. Причина:
индекс однажды был собран с `--fulltext`, затем пересобран без него.
`Reset()` в `internal/index/index.go:55` делает `DELETE FROM pages_fts`,
что лишь переносит страницы в freelist (~690 тыс. из ~1,1 млн страниц).
`VACUUM` нигде не вызывается.

Последствия: 4,5 ГБ копировать каждому участнику команды / на сервер,
медленнее холодный кеш, больше бэкапы. VACUUM занимает около 1,5 мин на
этой машине.

### 3. Производительность поиска на индексе в 2,6 млн записей (средний приоритет)

Замеры через CLI, прогретый кеш:

| Запрос | Путь | Время |
|---|---|---|
| `async function` | FTS глобально | 0,05 с |
| `get*` | FTS префикс | 0,52 с |
| `a*` | FTS префикс | 1,6 с |
| `zzqx` (нет совпадений в FTS) | LIKE-фолбэк, полный скан | 0,60–0,65 с |
| то же с фильтром по doc | LIKE по одной документации | 0,07 с |

Причины:

- `searchSubstring` (`internal/index/search.go:328`) выполняет `name LIKE
  '%q%'` по всей таблице `entries`; единственный вторичный индекс —
  `idx_entries_doc`, поэтому глобальный промах всегда полный скан таблицы.
- Префиксные запросы FTS5 на 1–2 символа затрагивают большую часть
  posting-списков. Опция `prefix=` на `entries_fts` не настроена.
- `catalogOnce` загружает каталог документаций при первом запросе, это
  нормально, но для пути чтения не настроен page cache (`cache_size`,
  `mmap_size`); bulk PRAGMA в `internal/index/pragma.go` действуют только
  во время сборки.

### 4. Усиление HTTP сервера для LAN (средний приоритет)

`cmd/marvindocs/main.go:192` создаёт `http.Server{Addr, Handler}` без
`ReadHeaderTimeout`, `ReadTimeout`, `IdleTimeout`. Медленный или зависший
клиент в сети может держать соединения бесконечно. В сочетании с
отсутствием авторизации по умолчанию и CSRF-проблемой `go-sdk` выше
стандартный `serve` слабее, чем должен быть для общего сервера.

Нет заголовков безопасности (`X-Content-Type-Options`,
`Content-Security-Policy`, `X-Frame-Options`) в веб-интерфейсе. Страницы
рендерятся из сторонних HTML-дампов, поэтому CSP хотя бы на страницах
`/d/...` имеет смысл.

### 5. Конфигурация линтера и тесты (низкий приоритет)

- `golangci-lint` нашёл 2 стилевых quick-fix замечания в корневом модуле;
  нет `.golangci.yml`, поэтому каждый запуск использует набор линтеров по
  умолчанию и результат не воспроизводим.
- Тесты `internal/index` идут около 4 минут (строят реальные FTS-таблицы
  из фикстур). Нет тестов в `cmd/marvindocs`, `internal/mcpserver`,
  `internal/web`.

### 6. Git и конвенции (информационно)

- 84 коммита, утечек секретов нет.
- Горячие точки за 6 месяцев: `cmd/marvindocs/main.go` (13 изменений),
  `scripts/sync-docs.sh` (11), `docs/*/cli.md` (10). `main.go`
  концентрирует разбор флагов, сборку сервера и авторизацию; естественный
  кандидат на разделение, если продолжит расти.
- Конвенции CLAUDE.md (docker compose, документация EN+RU в `docs/`, без
  смайлов в коммитах) соблюдаются; `scripts/check-docs-parity.sh` проходит.
- Docker-образ: 34 МБ, multi-stage, биндится на `0.0.0.0:3333`,
  healthcheck на `/healthz`. `docker compose up` требует заранее собранный
  `./data/index/marvindocs.db` (задокументировано).

## Рекомендуемый план

Упорядочен по пользе для развёртывания в LAN/команде относительно затрат.

### Фаза 1: быстрые победы (часы)

1. Поднять `go-sdk` до >= v1.4.1 (лучше v1.8.0) и `x/net` до >= v0.56.0 в
   корневом модуле; `x/net` в `parsers/go-dev`; `gomarkdown/markdown` в
   `parsers/laravel`. Прогнать `go test -tags sqlite_fts5 ./...` и
   smoke-тест MCP (`POST /mcp initialize`). Повторить `govulncheck`.
2. Выполнять `VACUUM` после `build` (и в `Reset()`, если предыдущий индекс
   содержал строки `pages_fts`), либо добавить подкоманду
   `marvindocs vacuum` с заметкой в `docs/*/cli.md`. Ожидание: 4,49 ГБ ->
   ~430 МБ.
3. Добавить `ReadHeaderTimeout`, `IdleTimeout` в `http.Server`.
4. Добавить `.golangci.yml` с зафиксированным текущим набором и исправить
   два quick-fix замечания.

### Фаза 2: усиление для LAN (полдня)

5. Сделать авторизацию обязательной для небезопасных биндов: отказываться
   стартовать на `0.0.0.0` без `--auth-token` / `MARVINDOCS_AUTH_TOKEN`,
   если не передан `--insecure`. Задокументировать в
   `docs/*/configuration.md`.
6. Добавить заголовки безопасности в веб-интерфейс; CSP, блокирующий
   inline-скрипты на отрендеренных страницах документации.
7. Прокинуть `MARVINDOCS_AUTH_TOKEN` через env в `docker-compose.yml` и
   добавить пример в `docs/*/getting-started.md`.

### Фаза 3: скорость поиска (1–2 дня)

8. Добавить `CREATE INDEX idx_entries_name ON entries(name COLLATE NOCASE)`
   и изменить фолбэк: сначала префиксный `LIKE 'q%'` (дружественный к
   индексу), затем скан `%q%` только если префиксная форма ничего не
   вернула. Ожидание: глобальный промах с 0,6 с до десятков мс в типичном
   случае.
9. Ограничить фолбэк: пропускать глобальный скан `%q%` для запросов короче
   3 символов или ограничивать его `LIMIT` плюс фильтром `doc`, когда
   клиент его передаёт.
10. Рассмотреть `prefix='2 3'` на `entries_fts` для ускорения префиксных
    запросов на 2–3 символа (стоит размера индекса; замерить на копии после
    VACUUM).
11. Применять PRAGMA для пути чтения при открытии: `cache_size` ~64 МБ,
    `mmap_size` ~256 МБ, `temp_store = MEMORY`. Дёшево и помогает
    холодному старту на сервере.

### Фаза 4: тесты и сопровождаемость (постоянно)

12. Smoke-тесты для `cmd/marvindocs` (флаги `serve`, `/healthz`, обработчик
    авторизации), `internal/web` (путь ETag/304, 404), `internal/mcpserver`
    (список инструментов, один вызов поиска) на `httptest`.
13. Разделить набор `internal/index`: оставить один небольшой тест на
    фикстурах в обычном запуске, полные тесты сборки убрать за `-short` /
    build tag, чтобы `go test ./...` проходил за секунды.
14. Добавить `govulncheck` и `golangci-lint` в `make check` (или job в CI).

## Что не делалось в этом аудите

- Файлы не менялись; VACUUM выполнялся только на копии.
- Нагрузочное тестирование с конкурентными клиентами не проводилось.
- Парсеры не проверялись глубже статического анализа и `govulncheck`.
