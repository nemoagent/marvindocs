# Справочник CLI

```
marvindocs <command> [flags]
```

Краткая справка — `marvindocs help` (также `--help` / `-h`).

## `marvindocs version`

Выводит версию сборки (по умолчанию `dev`, перезаписывается через
`-ldflags "-X main.version=..."`). Также принимается как `--version` / `-v`.

```bash
marvindocs version
# marvindocs dev
```

## `marvindocs index build`

Обновляет SQLite FTS5-индекс из дампа devdocs. По умолчанию режим
**инкрементальный**: документы, у которых `mtime` (из `meta.json`) не
изменился, пропускаются; исчезнувшие из дампа документы удаляются.
Первый запуск на пустом файле индекса эквивалентен полной сборке.
Эмбеддинги чанков неизменённых документов сохраняются (см.
[Векторный поиск](vectors.md)).

```bash
marvindocs index build [--docs-path DIR] [--index-path FILE] [--full [--drop-vectors]] [--rehash]
```

| Флаг | По умолчанию | Примечание |
|---|---|---|
| `--docs-path` | `data/public/docs` | Должен содержать `docs.json` и `<slug>/{index.json,db.zip}`. |
| `--index-path` | `marvindocs.db` | Выходной файл SQLite. Обновляется на месте. |
| `--full` | `false` | Принудительная полная пересборка (удалить всё и вставить заново). Деструктивна: если в индексе есть эмбеддинги чанков, отказывается работать без `--drop-vectors`. |
| `--drop-vectors` | `false` | Вместе с `--full`: подтверждает удаление всех эмбеддингов чанков (`chunk_vecs`). Пересчёт эмбеддингов всего дампа занимает часы. |
| `--rehash` | `false` | Пересчитать `docs.content_hash` у документов с неизменным `mtime` без переиндексации и повторных эмбеддингов. |

`--rehash` нужен один раз после [`marvindocs pack --all`](#marvindocs-pack)
на существующем индексе, потому что определение хеша содержимого
изменилось: теперь это SHA-256 от центрального каталога `db.zip` (имя
записи, CRC-32 и несжатый размер каждой записи), за которым идут байты
`index.json`; страницы не распаковываются. Без `--rehash` ничего не
ломается (неизменный `mtime` означает пропуск документа), но при
следующем изменении `mtime` с тем же содержимым документ будет
переиндексирован вместо простого обновления `mtime`.

После успешной сборки индекс уплотняется: сегменты FTS5 сливаются и,
если более 10% файла занимают свободные страницы, выполняется `VACUUM`
с checkpoint WAL. Иначе удалённые документы и пересборки `--full`
оставляют файл на пиковом размере.
Уплотнение пишется в лог как `index compacted reclaimed_mb=N`; если
освобождать нечего, шаг пропускается. Ориентир: около 30 с на 4 ГБ.

Рекомендуемый вариант — обычный `index build`: он инкрементальный и
сохраняет векторы. `--full` на индексе с векторами завершается ошибкой
вида `--full would discard N chunk embeddings ...`; добавляйте
`--drop-vectors`, только если векторы действительно нужно выбросить.

Коды выхода: `0` — успех, `1` — ошибка (нет данных, ошибка записи
SQLite и т.д.), `2` — ошибка использования.

> **Требования к сборке.** Драйвер SQLite — `github.com/mattn/go-sqlite3`,
> он использует CGo. `Makefile` собирает в контейнере `golang:1.25` с
> `CGO_ENABLED=1` и `-tags sqlite_fts5`. При ручной сборке оба условия
> обязательны — без `sqlite_fts5` расширение FTS5 не включается и индекс
> не откроется.

## `marvindocs index embed`

Считает эмбеддинги чанков в индекс (по умолчанию локальный ONNX, либо Ollama).
Обрабатываются только чанки без вектора, так что команду можно
перезапускать. Векторы использует гибридный поиск в `get_docs`, если
`serve` запущен с `--embedder`. После `index build` нужно пересчитать
только изменённые доки; `index build --full --drop-vectors` удаляет все векторы. Все
флаги — в разделе [Векторный поиск](vectors.md).

```bash
marvindocs index embed [--doc SLUG]... [--embedder ollama|onnx] [--batch N]
```

`--embedder` по умолчанию `onnx` (локально на CPU, медленно: для всего
дампа часы); флаги эмбеддера по умолчанию берутся из переменных
окружения `MARVINDOCS_*`, см. [Конфигурацию](configuration.md#переменные-окружения).

## `marvindocs index stats`

Выводит счётчики из готового индекса. С флагом `--by-doc` — таблица по
каждому документу, отсортированная по числу записей (по убыванию).
Помогает найти выбросы.

```bash
marvindocs index stats [--index-path FILE] [--by-doc] [--top N]
```

| Флаг | По умолчанию | Примечание |
|---|---|---|
| `--index-path` | `marvindocs.db` | Файл SQLite-индекса. |
| `--by-doc` | off | Печатать таблицу по документам после сводки. |
| `--top` | 0 (все) | В паре с `--by-doc` — ограничить топ N строк. |

Пример вывода (образец; числа зависят от вашего дампа):

```
index:   marvindocs.db
size:    476532736 bytes
docs:    791
entries: 2677981
pages:   0

SLUG                               ENTRIES       PAGES
openjdk~25                           49730           0
scala~3.1                            48073           0
qt~6.9                               45235           0
```

## `marvindocs search`

Выполняет полнотекстовый поиск по индексу и печатает результаты.
Удобно для shell-пайплайнов и быстрых проверок без запуска сервера.

```bash
marvindocs search QUERY [--doc SLUG] [--limit N] [--json] [--body] [--index-path FILE] [--docs-path DIR] [--synonyms DIR]
```

| Флаг | По умолчанию | Примечание |
|---|---|---|
| `--doc` | пусто | Ограничить поиск одним slug (например, `react`, `python~3.13`). Если флаг не задан, поиск авто-определяет doc-фильтр по токенам запроса: токен, совпадающий со slug'ом или его префиксом (до `~`/`-`), удаляется и применяется как фильтр; если так ничего не найдено, полный запрос ищется глобально. Работают и синонимы названия дока (`pg` -> `postgresql`, `golang` -> `go`), см. [Синонимы](synonyms.md). |
| `--limit` | `20` | Максимум результатов (1–100). |
| `--json` | `false` | Выводить сырой список результатов как JSON в stdout. |
| `--body` | `false` | Искать по телу страниц (Markdown-чанки, страница ранжируется по лучшему чанку), а не по именам записей. |
| `--index-path` | `marvindocs.db` | Файл SQLite-индекса (должен существовать). |
| `--docs-path` | `data/public/docs` | Используется с `--body` для сборки сниппетов из `db.zip`; без неё результаты выводятся без фрагментов. |
| `--synonyms` | пусто | Каталог с дополнительными файлами синонимов `*.md`, они добавляются к встроенному словарю; `off` отключает расширение запросов. Если флаг пуст — читается `MARVINDOCS_SYNONYMS`; см. [Синонимы](synonyms.md). |

Позиционные аргументы после флагов склеиваются через пробел, то есть
`marvindocs search http server` эквивалентно `marvindocs search "http server"`.

Текстовый вывод — колонки `DOC_SLUG  NAME  PATH` (с `--body`:
`DOC_SLUG  PATH  SNIPPET`). Итоговая строка
`N result(s)` пишется в stderr, чтобы было удобно передавать данные
по пайпу.

Код выхода `0` даже при отсутствии результатов (в stderr выводится
сообщение); `1` — ошибка индекса; `2` — ошибка использования.

## `marvindocs get`

Возвращает одну страницу из дампа devdocs в виде Markdown или
исходного HTML. SQLite-индекс не нужен — читает `<slug>/db.zip`
напрямую.

```bash
marvindocs get SLUG PATH [--format markdown|html] [--docs-path DIR]
```

| Флаг | По умолчанию | Примечание |
|---|---|---|
| `--format` | `markdown` | `markdown` (алиас `md`) или `html`. |
| `--docs-path` | `data/public/docs` | Каталог с `<slug>/db.zip`. |

`PATH` — путь страницы, как он хранится в devdocs (например
`hooks/use-state` для React). Узнать корректный путь можно через
`marvindocs search`.

## `marvindocs list`

Печатает документации, присутствующие в индексе, по одной в строке:

```bash
marvindocs list [--json] [--index-path FILE]
```

| Флаг | По умолчанию | Примечание |
|---|---|---|
| `--json` | `false` | Выводить список как JSON. |
| `--index-path` | `marvindocs.db` | Файл SQLite-индекса (должен существовать). |

Текстовый вывод — колонки `SLUG  NAME  VERSION` (если `version`
пусто, используется `release`). Итоговая строка идёт в stderr.

## `marvindocs pack`

Конвертирует документы из `<slug>/db.json` (JSON-карта path -> html,
формат архивов devdocs.io) в `<slug>/db.zip` (по одной сжатой deflate-
записи на страницу, см.
[Формат данных](data-format.md#5-slugdbzip--содержимое-страниц)) и
удаляет `db.json`. SQLite-индекс не нужен.

```bash
marvindocs pack (--all | SLUG...) [--docs-path DIR]
```

| Флаг | По умолчанию | Примечание |
|---|---|---|
| `--all` | `false` | Конвертировать все документы из `docs.json`. Несовместим с аргументами `SLUG`. |
| `--docs-path` | `data/public/docs` | Каталог данных с `<slug>/db.json`. |

Документы без `db.json` пропускаются, поэтому команду безопасно
запускать повторно. `scripts/sync-docs.sh` вызывает
`marvindocs pack <slug>` сразу после распаковки каждого скачанного
документа. `--all` мигрирует существующий каталог данных на месте
(около 12 минут на 830 документов); после этого один раз запусти
[`marvindocs index build --rehash`](#marvindocs-index-build). Результат
занимает на диске примерно в 4 раза меньше (полный набор devdocs:
~8 ГБ -> ~2.4 ГБ).

## `marvindocs serve`

Запускает MCP-сервер.

```bash
marvindocs serve [--stdio] [--http ADDR] [--auth-token TOKEN] [--insecure] \
                 [--docs-path DIR] [--index-path FILE] \
                 [--embedder none|ollama|onnx] [--ollama-url URL] \
                 [--ollama-model NAME] [--model-dir DIR] [--onnxruntime PATH] \
                 [--synonyms DIR]
```

| Флаг | По умолчанию | Примечание |
|---|---|---|
| `--stdio` | `false` | MCP через stdin/stdout. |
| `--http` | пусто | Web UI на `<addr>/` и MCP Streamable HTTP на `<addr>/mcp`. Голый `:3333` слушает только `127.0.0.1`; для публичного доступа — `0.0.0.0:3333`. |
| `--auth-token` | пусто | Если задан, каждый HTTP-запрос (включая `/mcp` и веб-интерфейс) должен содержать `Authorization: Bearer TOKEN`; исключение — только `/healthz`. Если флаг пуст — читается `MARVINDOCS_AUTH_TOKEN`. |
| `--insecure` | `false` | Разрешить `--http` на не-loopback адресе без токена. Без флага (или `MARVINDOCS_INSECURE=1`) `serve` отказывается стартовать на публичном адресе, если токен не задан. |
| `--docs-path` | `data/public/docs` | Нужен `get_page`, чтобы читать `db.zip` по требованию. |
| `--index-path` | `marvindocs.db` | Файл должен уже существовать (сначала `index build`). |
| `--embedder` | `none` | `none`, `ollama` или `onnx`. С эмбеддером `get_docs` использует гибридный поиск (векторы + BM25) по докам, у которых есть векторы. |
| `--ollama-url`, `--ollama-model` | `http://localhost:11434`, `bge-m3` | Настройки Ollama. |
| `--model-dir`, `--onnxruntime` | | onnx: каталог с моделью и путь к `libonnxruntime.so`. |
| `--synonyms` | пусто | Каталог с дополнительными файлами синонимов `*.md`, они добавляются к встроенному словарю; `off` отключает расширение запросов. Если флаг пуст — читается `MARVINDOCS_SYNONYMS`. Несуществующий каталог — ошибка при старте. См. [Синонимы](synonyms.md). |

Флаги эмбеддера те же, что у `index embed`; см.
[Векторный поиск](vectors.md).

Надо передать как минимум один из `--stdio` / `--http`. Оба можно
указать одновременно — один и тот же инстанс сервера обслуживает
оба транспорта.

Процесс слушает `SIGINT` и `SIGTERM` и при любом из них корректно
завершает работу, давая до 10 секунд in-flight HTTP-запросам.

HTTP-слушатель закрывает соединения, которые присылают заголовки
запроса дольше 10 с, и простаивающие keep-alive соединения через 120 с.
Таймаута записи нет: `/mcp` держит долгоживущие SSE-потоки.

При открытии индекса, собранного старой версией, недостающие объекты
схемы создаются на месте. Первый запуск после обновления до версии с
индексом `idx_entries_name` строит его сразу; на полном индексе devdocs
(2,6 млн записей) это занимает 30-40 с один раз.

### Логирование

Все команды учитывают две переменные окружения:

| Переменная | Значения | По умолчанию |
|---|---|---|
| `MARVINDOCS_LOG_LEVEL` | `debug`, `info`, `warn`, `error` | `info` |
| `MARVINDOCS_LOG_FORMAT` | `text`, `json` | `text` |

Логи пишутся в stderr. HTTP-сервер выводит одну строку на запрос
(method, path, status, dur_ms, remote).

## Коды выхода (для всех команд)

| Код | Значение |
|---|---|
| `0` | Успех |
| `1` | Ошибка времени выполнения (I/O, SQLite и т.д.) |
| `2` | Ошибка использования (неизвестный флаг, нет аргумента) |
