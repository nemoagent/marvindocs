# Синхронизация данных документации

marvindocs не поставляется с документацией devdocs. Вспомогательный
скрипт `scripts/sync-docs.sh` скачивает её напрямую с
`downloads.devdocs.io`, используя стандартные консольные утилиты — без
Docker, без Ruby, без клона devdocs.

## Требования

- `curl`, `tar`, `awk`, `xargs`, `stat`, `date`, `touch`

Ни Python, ни Docker, ни Ruby, ни `jq` — эти утилиты есть на любом
Linux, macOS и WSL из коробки.

Если `bin/marvindocs` отсутствует, а индекс перестраивается (без
`--no-index`/`--check`), скрипт сначала запускает `make build`, который
компилирует внутри Docker (см. `Makefile`).

## Быстрый старт

```bash
make build                    # собрать бинарь marvindocs (один раз)
./scripts/sync-docs.sh        # скачать 27 встроенных доков, перестроить индекс
./bin/marvindocs serve --http :3333
```

## Использование

```
./scripts/sync-docs.sh [DOCS...] [OPTIONS]
```

| Аргумент / опция | Значение |
|---|---|
| *(ничего)* | Скачать встроенный популярный набор (27 доков). |
| `react`, `python~3.13`, … | Только указанные slug'и. |
| `--all` | Обработать все slug'и из `data/public/docs/docs.json`. |
| `--check` | Dry-run: вывести таблицу up-to-date / outdated / missing и выйти, ничего не скачивая. |
| `--force` | Игнорировать локальный mtime — всегда перекачать запрошенные slug'и. |
| `--no-index` | Не перестраивать `marvindocs.db` после загрузки. |
| `--jobs N` | Параллельных загрузок (по умолчанию `8`). |
| `--list-remote` | Сходить в живой каталог devdocs.io и напечатать все доступные slug'и с именем и версией. Ничего не скачивает, индекс не трогает. |
| `--search-remote QUERY` | То же, что `--list-remote`, но оставляет только строки, где `slug` или `name` содержит `QUERY` (регистронезависимо). |
| `--help`, `-h` | Показать справку и выйти. |

### Примеры

```bash
# Несколько конкретных доков
./scripts/sync-docs.sh react vue~3 typescript python~3.13

# Просто посмотреть, что устарело — без скачивания
./scripts/sync-docs.sh --check --all

# Обновить всё, что уже лежит на диске (неизменившееся пропустится)
./scripts/sync-docs.sh --all

# Перекачать всё с нуля, даже если ничего не изменилось
./scripts/sync-docs.sh --all --force

# Скачать без перестройки индекса
./scripts/sync-docs.sh --all --no-index
./bin/marvindocs index build      # построить индекс вручную позже

# Посмотреть удалённый каталог перед скачиванием
./scripts/sync-docs.sh --list-remote | head
./scripts/sync-docs.sh --search-remote kubernetes
```

## Проверка обновлений

devdocs.io публикует единый каталог `https://devdocs.io/docs.json`, в
котором для каждого документа указан `mtime` сборки (unix timestamp).
При каждом запуске скрипт:

- забирает каталог **один раз** и читает `mtime` каждого slug'а;
- сравнивает его с fs-mtime локальной метки
  `data/public/docs/<slug>/.last-modified`;
- печатает `SKIP <slug> (up-to-date)`, если локальная метка не старше
  `mtime` из каталога — для этого slug'а сетевых запросов нет;
- иначе скачивает и распаковывает архив, печатает `UPDATED <slug>` и
  выставляет mtime метки равным значению из каталога
  (`touch -d @<remote_ts>`);
- для slug'а, которого нет в каталоге, отправляет один `HEAD`-запрос
  на `downloads.devdocs.io` и использует заголовок `Last-Modified`;
  если и это не удалось, но локальная метка есть — это дока, собранная
  парсером (`parsers/registry.json`): печатает `LOCAL ... (parser-built,
  skipped)` и не трогает её; если метки нет — `FAIL ... (not found)`;
- каталог с маркером `.parser` (его пишет `run-parser.sh` после каждого
  успешного запуска парсера, см. [Парсеры](parsers.md)) всегда
  помечается как `LOCAL` и никогда не перезаписывается, даже с `--force`
  и даже если на devdocs.io есть тот же slug (например `laravel~11`);
- `--force` отключает сравнение — всегда качать заново;
- `--check` только печатает таблицу статусов (`up-to-date`, `OUTDATED`,
  `MISSING`, `LOCAL (parser-built)`, `ERROR (no remote)`) и выходит,
  ничего не скачивая.

Парсеры из `parsers/` пишут ту же метку `.last-modified`, поэтому
сгенерированные локально документы укладываются в ту же структуру.

Почему файл-метка, а не поле `mtime` из `meta.json`? mtime метки
выставляется прямо из значения каталога, поэтому сравнение с каталогом
точное и не зависит от того, как был создан `meta.json`.

Прогонять скрипт ежедневно/еженедельно дёшево: один запрос каталога
плюс `HEAD` только для slug'ов, которых в каталоге нет.

## Что делает скрипт

1. Составляет список slug'ов (встроенный, `--all` из существующего
   `docs.json`, или указанные вручную).
2. Параллельно скачивает `https://downloads.devdocs.io/<slug>.tar.gz`
   через `curl` и распаковывает в `data/public/docs/<slug>/`.
   Неудачные slug'и (404/403) выводятся и пропускаются, скрипт не падает.
3. Пересобирает `data/public/docs/docs.json` из файлов `meta.json`
   каждого slug-каталога — чистый bash, без Python. Только если
   обновлён хотя бы один slug или `docs.json` отсутствует; иначе
   существующий файл остаётся как есть.
4. *(Если не передан `--no-index`)* Запускает `./bin/marvindocs index build`
   (инкрементально, эмбеддинги чанков сохраняются).

## Инкрементальная синхронизация индекса

`index build` решает для каждой доки отдельно:

- `mtime` не изменился: дока пропускается.
- `mtime` изменился, а содержимое нет: обновляется только сохранённый
  `mtime`, векторы доки сохраняются. Хеш содержимого — sha256 от
  `db.json` + `index.json`, он хранится в `docs.content_hash`. Это типичный
  случай после повторного запуска парсера, который переписывает файлы с
  тем же содержимым.
- Содержимое изменилось: дока переиндексируется, её старые векторы
  удаляются; `index embed` посчитает их заново.

В индексе, созданном старой версией, колонка `content_hash` добавляется
автоматически, а хеши заполняются при первом `index build`. См.
[Векторный поиск](vectors.md#обновление-векторов).

## Обновление одной командой

`make update` (то же, что `scripts/update.sh`) обновляет всё:

1. `sync-docs.sh --all --no-index` - доки с devdocs.io;
2. `run-parser.sh --all` - доки, собранные парсерами (пропускается, если
   нет бинарей `bin/*-parser`);
3. `marvindocs index build` - инкрементально;
4. `marvindocs index embed` - векторы для чанков, у которых их нет.

Индекс и векторы он никогда не удаляет. Настройки эмбеддера берутся из
`.env` (см. [Конфигурацию](configuration.md#файл-env)). Эмбеддер по
умолчанию - локальный ONNX на CPU, он медленный (для всего дампа часы);
скрипт печатает предупреждение об этом и подсказку, как переключиться на
Ollama через `.env`.

| Опция | Значение |
|---|---|
| `--no-parsers` | Пропустить шаг 2 (Docker и GitHub не нужны). |
| `--no-embed` | Пропустить шаг 4. |
| `--embed-only` | Только шаг 4 (это и запускает `make embed`). |
| `--index-only` | Только шаги 3-4. |

## Встроенный популярный набор

При запуске без аргументов скрипт скачивает:

```
angular     bash        c           cpp         css         django~5.2
docker      go          html        http        javascript  jinja~3.1
jquery      kubernetes  markdown    nginx       node        npm
postgresql~17  python~3.13  react   redis       ruby~3.4    rust
sqlite      typescript  vue~3
```

Чтобы изменить набор — отредактируй `DEFAULT_SLUGS` в начале файла
`scripts/sync-docs.sh`.

## Как найти нужный slug

Каждое название на <https://devdocs.io> — это slug для скачивания.
Версионные варианты используют тильду: `python~3.12`, `angular~18`,
`react~18`.

Смотреть живой каталог можно прямо из скрипта — браузер не нужен:

```bash
# Все доки живого каталога
./scripts/sync-docs.sh --list-remote

# Grep по slug или name (регистронезависимо)
./scripts/sync-docs.sh --search-remote python
./scripts/sync-docs.sh --search-remote "vue"
./scripts/sync-docs.sh --search-remote rust

# Пайп в shell
./scripts/sync-docs.sh --list-remote | awk 'NR>1 {print $1}' | sort > all-slugs.txt
```

Каталог берётся из `https://devdocs.io/docs.json` в момент запроса —
данные всегда актуальные.

Посмотреть, что уже лежит локально:

```bash
grep -o '"slug":"[^"]*"' data/public/docs/docs.json | cut -d'"' -f4
```

## Повторная синхронизация / обновление

Скрипт идемпотентен — повторный запуск перекачивает только те slug'и,
у которых `mtime` в каталоге новее локальной метки (или все, если
указан `--force`). Чтобы обновить только несколько доков:

```bash
./scripts/sync-docs.sh react vue~3
```

## Место на диске

| Набор | Примерный размер на диске |
|---|---|
| Встроенный (27 доков) | ~0,6 ГБ |
| Все slug'и каталога | ~17 ГБ |

Размеры измерены на локальном дампе и растут по мере появления новых
доков в devdocs. Время скачивания зависит от вашего канала.

## Коды возврата

- `0` — успех, даже если отдельные slug'и сообщили `FAIL`.
- `1` — не удалось получить каталог, либо `--all` не нашёл `docs.json`.
- `2` — неизвестная опция или `--search-remote` без запроса.
