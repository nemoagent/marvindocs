# Словарь синонимов

Поисковые запросы расширяются синонимами: `k8s` находит и `kubernetes`,
`regex` находит и `regular expression`. Словарь — это набор
Markdown-файлов: встроенный зашит в бинарь, а свои можно добавить.

## Формат файла

Формат тот же, что в графах знаний Terraphim / Logseq: один
Markdown-файл на одно понятие.

- Понятие — первая строка `# заголовок`; если заголовка нет, берётся имя
  файла без `.md`.
- Строка `synonyms:: a, b, c` перечисляет другие названия понятия. Ключ
  регистронезависим; несколько таких строк складываются.
- Каждое название понятия — синоним всех остальных названий.
- Остальные строки игнорируются.
- Читаются только файлы `*.md` в каталоге (без рекурсии).

Пример `regex.md`:

```
# regular expression

synonyms:: regex, regexp
```

Сравнение не зависит от регистра и идёт по целым словам. Название может
состоять из нескольких слов (`regular expression`); если в одном месте
подходит несколько названий, побеждает самое длинное многословное
совпадение.

## Настройка

| Флаг | Переменная окружения | Назначение |
|---|---|---|
| `--synonyms DIR` | `MARVINDOCS_SYNONYMS` | Каталог с дополнительным словарём. Флаг приоритетнее переменной. |

Флаг есть у `marvindocs serve` и `marvindocs search`.

| Значение | Эффект |
|---|---|
| пусто (по умолчанию) | Только встроенный словарь. |
| каталог | Его файлы `*.md` **добавляются** к встроенному словарю. |
| `off` | Расширение запросов полностью отключено, включая определение дока по синонимам. |

Несуществующий каталог — ошибка при старте.

```bash
marvindocs serve --http :3333 --synonyms ./my-synonyms
MARVINDOCS_SYNONYMS=off marvindocs search "k8s deployment"
```

Словарь загружается при старте: чтобы подхватить изменения, перезапустите
`serve`. Перестраивать индекс не нужно, потому что запрос расширяется во
время поиска.

## Как работает расширение

Каждый термин запроса, у которого есть синонимы, превращается в
OR-группу из самого термина и его синонимов в запросе SQLite FTS5.
Например, `k8s deployment` превращается в:

```
("k8s" OR "kubernetes"* OR "kube") AND "deployment"*
```

Расширение действует в:

- MCP-инструментах `search` (имена записей), `search_pages` и `get_docs`
  (лексическая часть, в том числе лексическая часть гибридного поиска);
- поиске веб-интерфейса;
- CLI: `marvindocs search` и `marvindocs search --body`.

Сниппеты тоже подсвечивают совпадения по синонимам.

### Авто-фильтр по документу

Авто-фильтр по документу (название дока в запросе ограничивает поиск этим
доком) тоже учитывает синонимы: `pg jsonb` ищет по `postgresql`,
`golang context` — по `go`. Это заменяет прежнюю жёстко прошитую таблицу
алиасов (`js`, `py`, `ts`, `pg`, `mongo`).

## Как дополнять словарь

Добавляйте только настоящие эквиваленты: сокращения, альтернативные
написания, переводы. OR-группа ранжирует каждый синоним наравне с исходным
словом, поэтому широкий синоним поднимает в выдаче слабо связанные
страницы.

## Заметка о бенчмарке

В бенчмарке `get_docs` из `internal/mcpserver` 96 кейсов. Результат с
встроенным словарём и без него:

| | hit@1 | hit@3 |
|---|---|---|
| синонимы включены | 47/96 | 72/96 |
| синонимы выключены | 47/96 | 72/96 |

Один кейс улучшился (`async await`: из промаха на 4-е место), ухудшений
нет. Широкие синонимы понятий (cleanup/teardown, hash map/dictionary)
пробовали и убрали из встроенного набора, потому что они ухудшали
ранжирование.

Чтобы запустить бенчмарк без синонимов, задайте `BENCH_SYNONYMS=off`.
