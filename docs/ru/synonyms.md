# Словарь синонимов

Поисковые запросы расширяются синонимами: `k8s` находит и `kubernetes`,
`regex` находит и `regular expression`. Словарь — это набор
Markdown-файлов: встроенный зашит в бинарь, а свои можно добавить.

## Формат файла

Формат тот же, что в графах знаний Terraphim / Logseq: один
Markdown-файл на одно понятие.

- Понятие — первая строка `# заголовок`; если заголовка нет, берётся имя
  файла без `.md`.
- Строка `synonyms:: a, b, c` перечисляет другие названия понятия. Ключ
  регистронезависим; несколько таких строк складываются.
- Каждое название понятия — синоним всех остальных названий.
- Остальные строки игнорируются.
- Читаются только файлы `*.md` в каталоге (без рекурсии).

Пример `regex.md`:

```
# regular expression

synonyms:: regex, regexp
```

Сравнение не зависит от регистра и идёт по целым словам. Название может
состоять из нескольких слов (`regular expression`); если в одном месте
подходит несколько названий, побеждает самое длинное многословное
совпадение.

## Настройка

| Флаг | Переменная окружения | Назначение |
|---|---|---|
| `--synonyms DIR` | `MARVINDOCS_SYNONYMS` | Каталог с дополнительным словарём. Флаг приоритетнее переменной. |

Флаг есть у `marvindocs serve` и `marvindocs search`.

| Значение | Эффект |
|---|---|
| пусто (по умолчанию) | Только встроенный словарь. |
| каталог | Его файлы `*.md` **добавляются** к встроенному словарю. |
| `off` | Расширение запросов полностью отключено, включая определение дока по синонимам. |

Несуществующий каталог — ошибка при старте.

```bash
marvindocs serve --http :3333 --synonyms ./my-synonyms
MARVINDOCS_SYNONYMS=off marvindocs search "k8s deployment"
```

Словарь загружается при старте: чтобы подхватить изменения, перезапустите
`serve`. Перестраивать индекс не нужно, потому что запрос расширяется во
время поиска.

## Как работает расширение

Каждый термин запроса, у которого есть синонимы, превращается в
OR-группу из самого термина и его синонимов в запросе SQLite FTS5.
Например, `k8s deployment` превращается в:

```
("k8s" OR "kubernetes"* OR "kube") AND "deployment"*
```

Расширение действует в:

- MCP-инструментах `search` (имена записей), `search_pages` и `get_docs`
  (лексическая часть, в том числе лексическая часть гибридного поиска);
- поиске веб-интерфейса;
- CLI: `marvindocs search` и `marvindocs search --body`.

Сниппеты тоже подсвечивают совпадения по синонимам.

### Авто-фильтр по документу

Авто-фильтр по документу (название дока в запросе ограничивает поиск этим
доком) тоже учитывает синонимы: `pg jsonb` ищет по `postgresql`,
`golang context` — по `go`. Это заменяет прежнюю жёстко прошитую таблицу
алиасов (`js`, `py`, `ts`, `pg`, `mongo`).

## Как дополнять словарь

Добавляйте только настоящие эквиваленты: сокращения, альтернативные
написания, переводы. OR-группа ранжирует каждый синоним наравне с исходным
словом, поэтому широкий синоним поднимает в выдаче слабо связанные
страницы.

## Сбор словаря из документации

Писать словарь вручную долго. `marvindocs synonyms suggest` собирает
кандидатов-аббревиатур из самих документов, а `marvindocs synonyms import`
превращает проверенную таблицу в файлы словаря.

### Поиск кандидатов: `synonyms suggest`

```bash
marvindocs synonyms suggest [--docs-path DIR] [--doc SLUG]... [--min-docs N] [--min-count N] \
                            [--names-only] [--synonyms DIR] [--out FILE]
```

Команда ищет пары вида `Server-Side Rendering (SSR)` или
`SSR (Server-Side Rendering)`. Аббревиатура (3-10 букв, минимум 2
заглавные, множественное `s` отбрасывается: `ASGs` -> `asg`) должна
состоять из первых букв слов названия по порядку. Каждое слово даёт хотя
бы одну букву; служебные слова вроде `of`, `and`, `the`, `for`, `in`, `to`
могут не дать ни одной. В названии должно быть не меньше двух слов; части
слова через дефис считаются отдельными словами. Перед аббревиатурой в
скобках берётся самая короткая цепочка предыдущих слов, которая её
складывает, поэтому `Migrating from Create React App (CRA)` даёт
`create react app`.

Сканируются имена записей (`index.json`) и текст страниц (`db.zip`) **одной
версии каждого дока** (последней скачанной, потому что версии повторяют
один и тот же текст), параллельно на всех ядрах. Версии одного дока
считаются за один док.

| Флаг | По умолчанию | Примечание |
|---|---|---|
| `--docs-path` | `data/public/docs` | Каталог с `docs.json` и `<slug>/{index.json,db.zip}`. |
| `--doc` | все доки | Сканировать только этот slug; можно повторять. Точные slug, включая версию. |
| `--min-docs` | `2` | Оставить пары, найденные минимум в N доках. |
| `--min-count` | `3` | Оставить пары, встреченные минимум N раз. |
| `--names-only` | `false` | Сканировать только имена записей: секунды вместо минут. |
| `--synonyms` | пусто | Тот же флаг и переменная `MARVINDOCS_SYNONYMS`, что у `serve`. Термины, у которых уже есть синонимы во встроенном словаре или в DIR, пропускаются, поэтому повторный запуск после импорта предложит только новое. |
| `--out` | stdout | Записать таблицу в файл. |

На полном архиве (830 доков, 234 названия доков, 2.7 ГБ `db.zip`):

| Режим | Время | Память | Кандидатов |
|---|---|---|---|
| `--names-only` | около 2 с | | 5 |
| полный текст | около 10 мин | около 500 МБ | около 420 |

Верхние строки полного запуска: `universally unique identifier` / `uuid`,
`transport layer security` / `tls`, `cross-origin resource sharing` /
`cors`, `content security policy` / `csp`, `abstract syntax tree` / `ast`,
`document object model` / `dom`, `server-side rendering` / `ssr`,
`json web token` / `jwt`, `common table expression` / `cte`.

### Фильтры

- Аббревиатура с несколькими значениями отбрасывается, если одно из
  значений не составляет хотя бы 60% её употреблений.
- Написания названия, отличающиеся конечным `s`, объединяются; в качестве
  понятия берётся единственное число, если оно встретилось.
- Несколько аббревиатур одного названия попадают в одну строку.
- Если в названии есть дефисы, его форма с пробелами добавляется как
  синоним (`server-side rendering` -> `ssr, server side rendering`),
  потому что запрос делится по пробелам.

### Формат вывода

TSV-таблица. Первая строка — комментарий-заголовок:

```
# concept<TAB>synonyms<TAB>count<TAB>docs<TAB>examples
```

| Колонка | Содержимое |
|---|---|
| `concept` | Полное название. |
| `synonyms` | Аббревиатуры и написания через запятую. |
| `count` | Число вхождений. |
| `docs` | Число доков, где найдена пара. |
| `examples` | До 5 имён доков в качестве примеров. |

Строки отсортированы по числу доков, затем по числу вхождений.

### Запись файлов: `synonyms import`

```bash
marvindocs synonyms import FILE --out DIR [--force]
```

`FILE` — таблица; `-` читает stdin. Его можно указать до флагов или после
них. Используются только первые две колонки (понятие и синонимы через
запятую); пустые строки и строки, начинающиеся с `#`, игнорируются;
строки одного понятия объединяются.

| Флаг | По умолчанию | Примечание |
|---|---|---|
| `--out` | обязателен | Каталог словаря; создаётся, если его нет. |
| `--force` | `false` | Перезаписывать существующие файлы. Без флага существующие файлы пропускаются, так что ручные правки сохраняются. |

На каждое понятие пишется один файл в [формате словаря](#формат-файла):
`# понятие`, пустая строка, `synonyms:: a, b`. Имя файла — понятие в
нижнем регистре, где каждая серия символов, не являющихся буквами или
цифрами, заменена на `-`, плюс `.md` (`server-side rendering` ->
`server-side-rendering.md`; кириллица сохраняется).

### Рекомендуемый порядок работы

1. Соберите кандидатов:
   ```bash
   marvindocs synonyms suggest --out synonyms.tsv
   ```
2. Проверьте таблицу. Удалите строки, у которых аббревиатура совпадает с
   обычным английским словом или иначе вредна для поиска: в реальном
   запуске это были `dos`, `pie`, `pic`, `cow`, `mic`, `des`, `tos`, `dst`
   (слово запроса `pie` искало бы и `position independent executables`).
   Удалите строки не по теме. Добавьте в колонку `synonyms` русские и
   другие переводы и написания. Первый проход по таблице может сделать
   LLM (попросите оставить только точные эквиваленты и добавить
   устоявшиеся русские термины), затем человек просматривает результат:
   это несколько сотен строк.
3. Запишите файлы словаря:
   ```bash
   marvindocs synonyms import synonyms.tsv --out synonyms/
   ```
4. Запустите сервер со словарём:
   ```bash
   marvindocs serve --synonyms synonyms/
   ```
   или задайте `MARVINDOCS_SYNONYMS=synonyms/`.
5. Сравните бенчмарк со словарём по умолчанию (см. заметку ниже).

Перестраивать индекс не нужно: запрос расширяется во время поиска.

## Заметка о бенчмарке

В бенчмарке `get_docs` из `internal/mcpserver` 96 кейсов. Результат с
встроенным словарём и без него:

| | hit@1 | hit@3 |
|---|---|---|
| синонимы включены | 47/96 | 72/96 |
| синонимы выключены | 47/96 | 72/96 |

Один кейс улучшился (`async await`: из промаха на 4-е место), ухудшений
нет. Широкие синонимы понятий (cleanup/teardown, hash map/dictionary)
пробовали и убрали из встроенного набора, потому что они ухудшали
ранжирование.

`BENCH_SYNONYMS` принимает `off` (совсем без синонимов) или каталог (он
добавляется к встроенному словарю, как `--synonyms`). Чтобы сравнить
словарь, собранный через `synonyms import`, со словарём по умолчанию:

```bash
BENCH_INDEX=marvindocs.db BENCH_DOCS=data/public/docs BENCH_SYNONYMS=synonyms \
  go test -tags sqlite_fts5 -run TestBench -v ./internal/mcpserver/
```
