# Проверки согласованности

Два вспомогательных скрипта проверяют целостность документации и дампа
devdocs. Запускайте их после `scripts/sync-docs.sh`, чтобы вовремя
обнаружить проблемы.

## check-docs-parity.sh

Проверяет синхронность `docs/en` и `docs/ru`:

- оба каталога содержат одинаковый набор `.md`-файлов (по относительному
  пути); файлы, которые есть только в `docs/ru`, тоже выводятся
- в каждом общем файле одинаковая упорядоченная последовательность
  уровней заголовков (`#`…`######`) — быстрая структурная проверка
  незавершённого перевода. Перестановка заголовков тоже приводит к
  ошибке; текст заголовков не сравнивается

Аргументы и опции отсутствуют.

### Использование

```bash
./scripts/check-docs-parity.sh
```

### Коды выхода

| Код | Значение |
|---|---|
| `0` | Оба языковых дерева согласованы. |
| `1` | Файл отсутствует в одном из деревьев или структура заголовков не совпадает. |
| `2` | Ошибка ввода/вывода — `docs/en` или `docs/ru` не найдены. |

### Пример вывода

```
OK: docs/en and docs/ru are consistent
```

При расхождении:

```
Files present in docs/en but missing in docs/ru:
  - new-feature.md
Heading structure differs: configuration.md (en=12, ru=11)
```

## check-devdocs-dump.sh

Проверяет целостность дампа devdocs на диске:

- `docs.json` присутствует в корне дампа и содержит валидный JSON
- для каждого slug из `docs.json`: файлы `index.json`, `db.zip` и
  `meta.json` существуют и непусты (пустые файлы выводятся как `EMPTY` и
  учитываются в «Missing/empty»); JSON-файлы должны содержать валидный
  JSON, а `db.zip` — проходить `unzip -t`
- директории slug'ов, присутствующие на диске, но отсутствующие в
  `docs.json`, выводятся как осиротевшие (orphan)

`jq` обязателен (запасного варианта нет), а для проверки `db.zip`
нужен `unzip`. Невалидный `docs.json`
прерывает проверку с кодом выхода `2`.

### Использование

```bash
./scripts/check-devdocs-dump.sh [--docs-path DIR]
```

### Опции

| Флаг | Значение по умолчанию | Примечание |
|---|---|---|
| `--docs-path DIR` | `data/public/docs` | Корень дампа для проверки. |

### Коды выхода

| Код | Значение |
|---|---|
| `0` | Проверка целостности дампа прошла успешно. |
| `1` | Найдена хотя бы одна проблема (отсутствующий файл, невалидный JSON, orphan-директория). |
| `2` | Ошибка использования, корень дампа / `docs.json` не найдены или `docs.json` — невалидный JSON. |

### Примеры

```bash
# Проверить расположение по умолчанию
./scripts/check-devdocs-dump.sh

# Проверить нестандартный путь
./scripts/check-devdocs-dump.sh --docs-path /custom/path
```

### Типичный сценарий

Запускайте после `scripts/sync-docs.sh`, чтобы обнаружить частично
загруженные или повреждённые slug'и. Любой slug с пометкой `MISSING`, `EMPTY`
или `INVALID` можно перекачать принудительно:

```bash
./scripts/sync-docs.sh --force <slug>
```

### Пример вывода

```
MISSING  rust/db.zip
ORPHAN   some-old-slug

Summary:
  OK slugs:       28
  Missing/empty:  1
  Invalid JSON:   0
  Orphan dirs:    1
```
