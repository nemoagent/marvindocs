# Формат данных DevDocs

Эта страница — **нормативное описание** формата на диске, который
читает marvindocs. Любой, кто пишет свой скрапер/парсер, может
ориентироваться ровно на эту схему — получившийся дамп без правок
подхватится командой `marvindocs index build` и `marvindocs serve`.

Вся информация ниже проверена по реальному дампу devdocs, с которым
работает этот проект.

## 1. Структура каталогов

```
<data-root>/
├── docs.json                 # каталог всех проиндексированных документов
├── <slug>/
│   ├── meta.json             # метаданные одного документа
│   ├── index.json            # entries + types
│   ├── db.json               # содержимое страниц, ключ — path
│   ├── .last-modified        # файл-метка: mtime = mtime документа (для sync-docs.sh)
│   ├── index.html            # опционально: то же, что db.json["index"]
│   └── <path>.html           # опционально: файл на каждую запись из db.json
├── <other-slug>/
│   └── ...
```

- `<data-root>` — это то, что ты передаёшь через `--docs-path`
  (по умолчанию `data/public/docs`).
- `<slug>` — идентификатор документа (нижний регистр, ASCII; `~`
  допустим для версионных вариантов, например `python~3.12`).
- `.last-modified` — пустой файл-метка, fs-mtime которого равен `mtime`
  документа. `scripts/sync-docs.sh` сравнивает его с удалённым каталогом,
  чтобы решить, нужно ли перекачивать документ; сам marvindocs его не
  читает. Парсеры из `parsers/` тоже его пишут.
- Файлы `.html` — удобство для прямой раздачи из файловой системы.
  marvindocs **их не читает**, он читает только `.json`. Их можно
  смело не писать, чтобы сэкономить диск.

## 2. `docs.json` — глобальный каталог

JSON-**массив** объектов, по одному на документ.

```json
[
  {
    "name":        "Angular",
    "slug":        "angular",
    "type":        "angular",
    "links":       { "home": "https://angular.dev/",
                     "code": "https://github.com/angular/angular" },
    "version":     "",
    "release":     "21.2.0",
    "mtime":       1772652661,
    "db_size":     10014653,
    "attribution": "Super-powered by Google ...",
    "alias":       "ng"
  }
]
```

| Поле | Тип | Обязательное | Примечание |
|---|---|---|---|
| `name` | string | да | Название для человека ("Angular", "Python", "React"). |
| `slug` | string | да | Должен совпадать с именем каталога под `<data-root>`. Нижний регистр ASCII; `~` допустим для версионных вариантов. |
| `type` | string | да | Логическое семейство (`"angular"`, `"python"`). Используется для группировки связанных slug'ов. |
| `version` | string | да | Может быть пустой. Человеко-читаемая метка рядом с `name`. |
| `release` | string | да | Может быть пустой. Конкретный релиз, например `"21.2.0"`. |
| `mtime` | integer | да | Unix time (в секундах) последней пересборки. |
| `db_size` | integer | да | Размер несжатого `db.json` в байтах. marvindocs использует только как информационный. |
| `links` | object | нет | Map string→URL. Типовые ключи — `home`, `code`. Выводится как есть. |
| `attribution` | string | нет | HTML-сниппет с указанием авторства/лицензии. |
| `alias` | string | нет | Короткое имя (`"ng"` для Angular). marvindocs сохраняет, но не использует. |

**Инварианты**

- Для каждого `slug` в `docs.json` должен существовать каталог
  `<data-root>/<slug>/` как минимум с `index.json` и `db.json`.
- Значения `slug` уникальны в массиве.
- Порядок элементов любой — marvindocs сортирует по `slug`, где нужно.

## 3. `<slug>/meta.json` — метаданные одного документа

Один JSON-объект с **теми же полями**, что и соответствующая запись в
`docs.json` (поля `attribution` и `alias` здесь тоже опциональны).
Пример:

```json
{
  "name":   "Angular",
  "slug":   "angular",
  "type":   "angular",
  "links":  { "home": "https://angular.dev/",
              "code": "https://github.com/angular/angular" },
  "version": "",
  "release": "21.2.0",
  "mtime":   1772652661,
  "db_size": 10014653
}
```

`meta.json` удобен для отдельных инструментов, которые хотят прочитать
один документ, не подхватывая глобальный `docs.json`. Сам marvindocs
читает только `docs.json` и игнорирует `meta.json`, но производитель
обязан держать их в синхронизации.

## 4. `<slug>/index.json` — каталог для поиска

Один JSON-объект:

```json
{
  "entries": [
    { "name": "$localize",            "path": "api/localize/init/$localize",   "type": "localize" },
    { "name": "$locationShim",        "path": "api/common/upgrade/$locationshim", "type": "common" }
  ],
  "types": [
    { "name": "animations", "count": 36, "slug": "animations" },
    { "name": "aria",       "count": 31, "slug": "aria" }
  ]
}
```

### 4.1 `entries[]`

По одной записи на каждый навигируемый символ / фрагмент страницы.

| Поле | Тип | Обязательное | Примечание |
|---|---|---|---|
| `name` | string | да | То, что пользователь видит в результатах поиска (`"useState"`). |
| `path` | string | да | Путь до записи. См. §4.3. |
| `type` | string | да | Одно из значений `types[].name` в этом же файле. |

Запись **уникальна по `(name, path)`** — одно и то же имя может
встречаться по нескольким путям (например, `useState` в `react` и
`react~18`).

### 4.2 `types[]`

По одной записи на категорию. Используется только для группировки.
marvindocs не требует `types[]`, но сохраняет, если он есть.

| Поле | Тип | Обязательное | Примечание |
|---|---|---|---|
| `name` | string | да | Метка для человека. Совпадает с `entries[].type`. |
| `count` | integer | да | Число записей этого типа. Только информация — marvindocs пересчитает сам. |
| `slug` | string | да | Короткий slug категории (используется в URL'ах UI devdocs.io; marvindocs игнорирует). |

### 4.3 Формат `path`

`path` — это либо:

- **`"foo/bar"`** — ссылается на страницу `db.json["foo/bar"]`.
- **`"foo/bar#fragment"`** — ссылается на подраздел той же страницы;
  смотри `db.json["foo/bar"]` и прокрути к якорю `#fragment`.

Как ключ в `db.json` используется **только часть до `#`**. Всё, что
после `#`, пробрасывается как есть в браузер/потребителя.

В эталонном дампе ~80% записей имеют `#fragment` (ведут в подраздел
большой страницы), ~20% — на отдельную страницу.

## 5. `<slug>/db.json` — содержимое страниц

JSON-**объект** (строка → строка):

```json
{
  "index":        "<h1>Angular</h1> ...",
  "guide/ssr":    "<h2>Server-side rendering</h2> ...",
  "api":          "<section>...</section>"
}
```

- **Ключи** — пути страниц. Любая запись `index.json`, у которой
  `path` (без `#fragment`) не является ключом здесь, — недостижима;
  marvindocs молча пропускает такие записи при раздаче.
- **Значения** — **HTML-фрагменты**, не полные документы. В них не
  должно быть `<html>`, `<head>`, `<body>`, `<link rel="stylesheet">`.
  Считай, что фрагмент будет вставлен в уже оформленную внешнюю
  страницу.

Одна страница может быть большой (десятки КБ HTML) — весь файл для
Angular ~10 МБ, для Ansible ~270 МБ. marvindocs не держит раскодированный
`db.json` в памяти: при первом обращении файл сканируется один раз, чтобы
запомнить байтовые границы каждого значения (несколько сотен КБ на док,
кеш по slug'у), а дальше отдельные страницы читаются позиционным чтением.

### 5.1 Что разрешено

- Стандартные блочные и строчные элементы (`<h1>`–`<h6>`, `<p>`, `<ul>`,
  `<ol>`, `<li>`, `<table>`, `<pre>`, `<code>`, `<a>`, `<img>`, `<em>`,
  `<strong>`, `<div>`, `<span>`, …).
- Относительные ссылки вида `<a href="foo/bar">` — браузер разрешит их
  относительно текущего URL страницы. Якорные ссылки
  (`<a href="#section">`) работают как обычно.
- Внешние `<img src="https://…">` — грузятся напрямую с оригинального
  хоста; marvindocs ничего не проксирует и не переписывает.
- Инлайновые `style="..."` и `<svg>` разрешены.

### 5.2 Что запрещено

- Никаких `<script>`, `<iframe>`, `<form>` — они исполняются в
  контексте внешней страницы и нарушают изоляцию. Сейчас marvindocs
  явно их не вырезает, но будущая санитизация может.
- Никаких `<!DOCTYPE>`, `<html>`, `<head>`, `<body>`.
- Никакого документного `<title>` — для заголовка страницы используй
  `<h1>`.

## 6. Опциональные `.html`-файлы

В некоторых дампах рядом с каждой записью `db.json` лежит
соответствующий `.html`:

```
angular/
├── db.json
├── index.html         # == db.json["index"]
└── guide/
    └── ssr.html       # == db.json["guide/ssr"]
```

Их содержимое **байт-в-байт** совпадает с соответствующим значением
из `db.json`. Они нужны только затем, чтобы Rails-приложение devdocs
могло отдавать их как статику. marvindocs их **не** использует —
в своих дампах ты можешь их вообще не создавать.

## 7. Кодировка и пробелы

- Все JSON — **UTF-8** без BOM.
- Запятых после последнего элемента нет; строго стандартный JSON.
- HTML-фрагменты могут содержать любой валидный UTF-8, включая
  символы вне BMP и HTML-сущности.

## 8. Минимальный алгоритм производителя

Для того, кто пишет новый скрапер, минимальный набор шагов:

1. Для каждого документа, который хочешь опубликовать, сгенерируй
   HTML-фрагменты для всех достижимых страниц. Сложи в плоскую карту
   `path -> html`.
2. Сгенерируй `index.json`, перечислив все навигируемые символы с
   полями `name`, `path` (опционально с `#fragment`) и `type`.
3. Агрегируй `types[]`; предподсчитай `count`.
4. Запиши `db.json` (карта из шага 1).
5. Запиши `meta.json` с идентичностью документа.
6. Обработав все документы, запиши глобальный `docs.json` —
   по одной записи на каждый получившийся `meta.json`.

После этого `marvindocs index build` подхватит всё за один проход.

## 9. Версионные варианты

Когда один продукт ведёт несколько версий документации, используй
`~` в slug'е:

```
python~3.11
python~3.12
python~3.13
```

Каждый вариант полностью независим (своя запись в `docs.json`, свой
каталог, свой `db.json`). В marvindocs нет специальной обработки —
это просто разные документы, у которых обычно одинаковый `type`
(`"python"`).

## 10. Ожидания по размеру

Замерено на полном дампе (830 документов):

- `docs.json`: ~175 КБ (один JSON-объект на документ).
- `meta.json`: обычно ~200 байт.
- `index.json`: 1 КБ — 8 МБ на документ, медиана ~100 КБ.
- `db.json`: 30 КБ — 280 МБ на документ, медиана ~3 МБ.

Планируй диск соответственно: итоговый размер зависит от того, сколько
документов ты хранишь. Размер собственного индекса marvindocs тоже
зависит от набора документов; он токенизирует тела страниц, но не хранит
их, поэтому остаётся заметно меньше суммарного размера `db.json`.
