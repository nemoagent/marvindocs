# Project audit (May 2026)

Scope: Go server `marvindocs` (MCP + web, SQLite FTS5 index), parsers in
`parsers/*`, Docker, scripts, docs. Target deployment: a LAN/team server and
local workstations, not the public internet.

Russian version: [../ru/audit-2026-05.md](../ru/audit-2026-05.md).

## Method

- Static analysis: `go vet`, `staticcheck`, `golangci-lint v2.13.2`, root
  module and all 5 parser modules, with `-tags sqlite_fts5`.
- Dependencies: `govulncheck` (symbol level), `go list -m -u`.
- Secrets: `gitleaks` over 84 commits, plus a `git grep` for hardcoded tokens.
- Code review of `internal/index`, `internal/docstore`, `internal/web`,
  `internal/mcpserver`, `cmd/marvindocs` (read-only).
- Measurements on the real index (`marvindocs.db`, 4.49 GB, 830 docs,
  2 624 539 entries, 0 full-text pages) and on a VACUUM'ed copy.
- Git hotspots over the last 6 months.

## Summary

| Area | Result |
|---|---|
| go vet / staticcheck | clean everywhere |
| golangci-lint | 2 quick-fix hints in the root module, no `.golangci.yml` |
| Vulnerable deps (reached code) | 9 in root (`x/net` 5, `go-sdk` 4), 5 in `parsers/go-dev`, 1 in `parsers/laravel` |
| Secrets | none found |
| Index size | 4.49 GB on disk, 429 MB after VACUUM (about 90% is free pages) |
| Search latency | FTS 0.05 s typical, 0.5-1.6 s for short/common prefixes, LIKE fallback 0.6 s full scan |
| Tests | `internal/index` suite takes about 4 min; no tests in `cmd`, `mcpserver`, `web` |

## Findings

### 1. Dependencies with known vulnerabilities (high)

`govulncheck` reports code paths that are actually executed.

Root module:

- `golang.org/x/net v0.53.0`, reached via `html.Parse`:
  GO-2026-5030, 5029, 5028, 5027, 5025 (XSS via duplicate attributes, DoS
  on arbitrary HTML, foreign-content handling). Fixed in v0.55.0; v0.56.0
  also clears the two "required but not called" ones (GO-2026-5942, 5026).
- `github.com/modelcontextprotocol/go-sdk v1.0.0`, reached from
  `cmd/marvindocs/main.go` and `internal/mcpserver/server.go`:
  GO-2026-5771 (DNS rebinding protection off by default on localhost),
  GO-2026-4773 (cross-site tool execution for HTTP servers without auth),
  GO-2026-4770 (NUL in JSON), GO-2026-4569 (case sensitivity). Fixed in
  v1.4.1; latest is v1.8.0.

Parsers:

- `parsers/go-dev`: same 5 `x/net` issues via `dev.extractArticle`
  (`parse.go:70`).
- `parsers/laravel`: GO-2026-5208, out-of-bounds read in
  `gomarkdown/markdown` `SmartypantsRenderer`; fixed in
  `v0.0.0-20260411013819-759bbc3e3207`.

The two `go-sdk` issues matter most for a LAN deployment: a browser on the
same network can hit `POST /mcp` unless `--auth-token` is set. Today the
token is optional.

Other outdated direct deps: `html-to-markdown/v2` 2.5.0 -> 2.5.2,
`go-sqlite3` 1.14.42 -> 1.14.52.

### 2. Index file is ~10x larger than needed (high, cheap fix)

`marvindocs.db` is 4.49 GB; a VACUUM'ed copy is 429 MB. Cause: the index
was built once with `--fulltext`, then rebuilt without it. `Reset()` in
`internal/index/index.go:55` does `DELETE FROM pages_fts`, which only moves
pages to the freelist (freelist ~690k of ~1.1M pages). Nothing ever runs
`VACUUM`.

Effects: 4.5 GB to copy to every team member / server, slower cold cache,
larger backups. VACUUM takes about 1.5 min on this machine.

### 3. Search performance on the 2.6M-entry index (medium)

Measured with the CLI, warm cache:

| Query | Path | Time |
|---|---|---|
| `async function` | FTS global | 0.05 s |
| `get*` | FTS prefix | 0.52 s |
| `a*` | FTS prefix | 1.6 s |
| `zzqx` (no FTS hit) | LIKE fallback, full scan | 0.60-0.65 s |
| same with doc filter | LIKE on one doc | 0.07 s |

Causes:

- `searchSubstring` (`internal/index/search.go:328`) runs `name LIKE
  '%q%'` over all of `entries`; the only secondary index is
  `idx_entries_doc`, so a global miss is always a full table scan.
- FTS5 prefix queries on 1-2 characters touch most of the posting lists.
  No `prefix=` index option is configured on `entries_fts`.
- `catalogOnce` loads the doc catalog on first request, fine, but no page
  cache tuning (`cache_size`, `mmap_size`) is applied for the read path;
  bulk PRAGMAs in `internal/index/pragma.go` are build-time only.

### 4. HTTP server hardening for LAN (medium)

`cmd/marvindocs/main.go:192` creates `http.Server{Addr, Handler}` with no
`ReadHeaderTimeout`, `ReadTimeout`, `IdleTimeout`. A slow or stuck client on
the LAN can hold connections indefinitely. Combined with no auth by default
and the `go-sdk` CSRF issue above, the default `serve` is weaker than it
should be for a shared server.

No security headers (`X-Content-Type-Options`, `Content-Security-Policy`,
`X-Frame-Options`) on the web UI. Pages are rendered from third-party HTML
dumps, so a CSP at least on `/d/...` pages is worthwhile.

### 5. Lint configuration and tests (low)

- `golangci-lint` found 2 quick-fix style hints in the root module; there is
  no `.golangci.yml`, so every run uses the default linter set and the result
  is not reproducible.
- `internal/index` tests take about 4 minutes (they build real FTS tables
  from fixtures). No tests in `cmd/marvindocs`, `internal/mcpserver`,
  `internal/web`.

### 6. Git and conventions (informational)

- 84 commits, no leaked secrets.
- Hotspots over 6 months: `cmd/marvindocs/main.go` (13 changes),
  `scripts/sync-docs.sh` (11), `docs/*/cli.md` (10). `main.go` concentrates
  flag parsing, server wiring and auth; it is the natural candidate for a
  split if it keeps growing.
- CLAUDE.md conventions (docker compose, EN+RU docs under `docs/`, no
  emoji in commits) are followed; `scripts/check-docs-parity.sh` passes.
- Docker image: 34 MB, multi-stage, binds `0.0.0.0:3333`, healthcheck on
  `/healthz`. `docker compose up` requires a prebuilt
  `./data/index/marvindocs.db` (documented).

## Recommended plan

Ordered by value for a LAN/team deployment versus effort.

### Phase 1: quick wins (hours)

1. Bump `go-sdk` to >= v1.4.1 (ideally v1.8.0) and `x/net` to >= v0.56.0
   in the root module; `x/net` in `parsers/go-dev`; `gomarkdown/markdown`
   in `parsers/laravel`. Run `go test -tags sqlite_fts5 ./...` and the MCP
   smoke test (`POST /mcp initialize`). Re-run `govulncheck`.
2. Run `VACUUM` after `build` (and in `Reset()` when the previous index
   had `pages_fts` rows), or add a `marvindocs vacuum` subcommand plus a
   note in `docs/*/cli.md`. Expected: 4.49 GB -> ~430 MB.
3. Add `ReadHeaderTimeout`, `IdleTimeout` to the `http.Server`.
4. Add `.golangci.yml` with the current default set pinned and fix the two
   quick-fix hints.

### Phase 2: LAN hardening (half a day)

5. Make auth the default for non-loopback binds: refuse to start on
   `0.0.0.0` without `--auth-token` / `MARVINDOCS_AUTH_TOKEN` unless
   `--insecure` is given. Document it in `docs/*/configuration.md`.
6. Add security headers to the web UI; a CSP that blocks inline scripts on
   rendered doc pages.
7. Add `docker-compose.yml` env wiring for `MARVINDOCS_AUTH_TOKEN` and an
   example in `docs/*/getting-started.md`.

### Phase 3: search speed (1-2 days)

8. Add `CREATE INDEX idx_entries_name ON entries(name COLLATE NOCASE)` and
   change the fallback to a prefix `LIKE 'q%'` first (index-friendly), then
   the `%q%` scan only when the prefix form returns nothing. Expected: global
   miss from 0.6 s to tens of ms for the common case.
9. Cap the fallback: skip the global `%q%` scan for queries shorter than 3
   characters, or bound it with `LIMIT` plus a `doc` filter when the client
   gives one.
10. Consider `prefix='2 3'` on `entries_fts` to speed up 2-3 character
    prefix queries (costs index size; measure on the VACUUM'ed copy).
11. Apply read-path PRAGMAs on open: `cache_size` ~64 MB, `mmap_size`
    ~256 MB, `temp_store = MEMORY`. Cheap and helps the cold start on a
    server.

### Phase 4: tests and maintainability (ongoing)

12. Smoke tests for `cmd/marvindocs` (`serve` flags, `/healthz`, auth
    handler), `internal/web` (ETag/304 path, 404), `internal/mcpserver`
    (tool list, one search call) using `httptest`.
13. Split the `internal/index` suite: keep one small fixture-based test in
    the default run, move the full build tests behind `-short` /
    a build tag so `go test ./...` finishes in seconds.
14. Add `govulncheck` and `golangci-lint` to `make check` (or a CI job).

## Not done in this audit

- No files were changed; VACUUM was run on a copy only.
- No load testing with concurrent clients.
- Parsers were not reviewed beyond static analysis and `govulncheck`.
